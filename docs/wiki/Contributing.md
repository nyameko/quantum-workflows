# Contributing curriculum and research workflows

Before submitting a notebook, search [issues](https://github.com/nyameko/quantum-workflows/issues) and the master academy plan for an existing track. Contributions should include learning objectives, math/physics prerequisites, the native SDK/API used, reproducible local path, inputs/outputs, analytic/numerical checks, tolerances, license/attribution, exercise solutions or test oracle, scientific sources and limitations.

Code PRs require lint and non-hardware tests, explicit provider extras, artifact schema compatibility and updated examples/docs. Do not merge a new curriculum label if no actual notebook or test exists. A planned module remains labelled planned.

For help, provide a public reproducible minimal script/notebook, supported Python and SDK versions, expected physics, sanitized trace and output manifest. Report secrets privately. See [Developer guide](Developer-guide.md) and [Wiki policy](https://github.com/nyameko/quantum-workflows/blob/main/docs/WIKI_PUBLISHING.md).
